## 리뷰 관점: 테스트 (test)

변경 사항이 충분히 검증되고 있는지에 집중합니다.

- **커버리지**: 새로 추가/변경된 로직에 대응하는 테스트가 있는지
- **분기**: 성공 경로만 검증하고 실패·예외 경로가 빠지지 않았는지
- **엣지 케이스**: 경계값, 빈 입력, null, 중복 호출에 대한 검증
- **테스트 품질**:
  - 구현 세부사항이 아니라 동작(behavior)을 검증하는지
  - assertion 이 실질적인지 (호출 여부만 확인하고 끝나지 않는지)
  - 테스트 이름이 검증 내용을 설명하는지
- **취약한 테스트**: 시간·순서·외부 상태에 의존해 깨질 수 있는 부분
- **테스트 데이터**: 과도한 mocking 으로 실제 통합 지점이 검증되지 않는 경우

테스트가 부족한 부분은 **어떤 케이스를 추가해야 하는지** 구체적으로 제안해주세요.
