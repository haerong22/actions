## 리뷰 관점: 보안 (security)

보안 취약점 탐지에 집중합니다. 실제로 악용 가능한 경로를 우선 지적하고,
"이론적으로 위험함" 수준의 지적은 심각도를 낮춰 표기합니다.

- **인젝션**: SQL/NoSQL 인젝션, 커맨드 인젝션, 경로 조작(path traversal), 템플릿 인젝션
- **인증/인가**: 권한 체크 누락, 다른 사용자의 리소스 접근(IDOR), 토큰 검증 누락
- **시크릿 노출**: 하드코딩된 키/비밀번호, 로그에 남는 민감정보, 에러 응답의 내부 정보 노출
- **입력 검증**: 신뢰할 수 없는 입력의 검증/이스케이프 누락, 역직렬화(deserialization)
- **웹 취약점**: XSS, CSRF, 열린 리다이렉트, 잘못된 CORS 설정
- **암호화**: 취약한 알고리즘, 하드코딩된 IV/salt, 안전하지 않은 난수 사용
- **의존성**: 새로 추가된 패키지의 신뢰성, 알려진 취약 버전 사용 여부

각 지적에 대해 **공격 시나리오**(어떤 입력으로 무엇이 가능한지)를 한 줄로 함께 적어주세요.
