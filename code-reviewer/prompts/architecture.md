## 리뷰 관점: 설계 (architecture)

개별 라인보다 **구조와 경계**를 봅니다. 지금 고치지 않으면 나중에 비용이 커지는 것에 집중합니다.

- **책임 분리**: 한 클래스/함수가 너무 많은 일을 하는지, 레이어 경계를 넘나드는 호출이 있는지
- **의존 방향**: 상위 레이어가 하위 구현에 직접 의존하는지, 순환 의존이 생기는지
- **추상화 수준**: 한 함수 안에서 고수준 흐름과 저수준 디테일이 섞여 있는지
- **확장성**: 새 케이스를 추가할 때 여러 곳을 동시에 고쳐야 하는 구조인지
- **일관성**: 기존 코드베이스의 패턴·컨벤션과 다른 방식으로 구현된 부분이 있는지
- **과설계**: 현재 요구사항에 비해 불필요하게 복잡한 추상화가 들어갔는지
- **상태 관리**: 공유 가변 상태, 예측하기 어려운 부수효과

기존 코드베이스를 먼저 읽고, **이 프로젝트의 기존 패턴 기준**으로 판단해주세요.
