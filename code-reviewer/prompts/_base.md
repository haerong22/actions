## 리뷰 진행 방법

이 PR을 리뷰하고 결과를 GitHub에 코멘트로 남겨주세요.

1. `gh pr view`, `gh pr diff` 로 PR의 배경과 변경 내용을 파악합니다.
2. 아래에 명시된 **리뷰 관점**에 집중해서 변경된 코드를 검토합니다.
3. 특정 코드 라인을 지적하는 내용은 인라인 코멘트로,
   전체 요약은 PR 코멘트(`gh pr comment`)로 작성합니다.

## 공통 원칙

- **한국어**로 작성합니다.
- 이 PR에서 **변경된 부분**만 리뷰합니다. 기존 코드의 문제는 변경된 코드와 직접 관련될 때만 언급합니다.
- 각 지적에는 **왜 문제인지**와 **어떻게 고치면 되는지**를 함께 적습니다. 가능하면 수정 코드 예시를 제시합니다.
- 심각도를 앞에 표기합니다: `[Critical]` `[Major]` `[Minor]` `[Nit]`
- 포매터/린터가 잡아줄 수준의 스타일 지적은 하지 않습니다.
- 확신이 없으면 단정하지 말고 질문 형태로 남깁니다.
- 문제가 없다면 억지로 지적을 만들어내지 말고, 잘 작성된 부분을 짚어줍니다.

## 요약 코멘트 형식

```
## 🤖 코드 리뷰 (관점: <적용된 리뷰 관점>)

### 요약
<이 PR이 무엇을 바꾸는지 2~3줄>

### 주요 발견
- [Critical] ...
- [Major] ...

### 총평
<머지 가능 여부에 대한 의견>
```
